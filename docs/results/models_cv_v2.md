## Unseen-fault behaviour

- **cpu_burn (never in any training set; out-of-fold)**: abstained on **97%** of 93 windows (novelty gate 97%; confidence below 0.40: 0%). For comparison the confidence rule alone abstains on 0%. When it did answer it said: {'down': 3}
- false abstention on KNOWN-class windows (out-of-fold): 0.9% (gate alone 0.9%); nested estimate with thresholds chosen inside training folds: 1.0%

Leave-one-fault-type-out: each supported fault type is removed from training entirely (all of its runs), the confidence threshold and the novelty-gate threshold are both chosen on the remaining runs only, and the held-out type is then shown to the model.

- Reading: a held-out type that is answered is answered WRONGLY by construction (the model has no label for it), so 'answered' is the share of unseen-type windows where the system would have guessed. A model that never abstains would show 0%. Some held-out types resemble a known one (a bad deploy looks like an error spike), which no feature-space distance can fully separate.
