## Unseen-fault behaviour

- **cpu_burn (never in any training set)**: abstained on 0% of 100 windows at threshold 0.55; when it did answer, it said: {'healthy': 100}

Leave-one-fault-type-out: each supported fault type is removed from training entirely (all of its runs), the threshold is chosen on the remaining runs only, and the held-out type is then shown to the model.

- for comparison, on KNOWN classes the nested procedure abstains on 3% of windows (false abstention).
- Reading: a model that never abstains would show 0% abstained above. Whatever the numbers are, a held-out type that is answered is answered WRONGLY by construction (the model has no label for it), so 'wrongly answered' is the share of unseen-type windows where the system would have guessed.
