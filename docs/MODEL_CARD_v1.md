## Components

- **Detector** (per service): IsolationForest on 10 traffic-normalised features, threshold = largest healthy validation score + slack, plus learned healthy-range limits per feature. Features: ['lat_ratio', 'cpu_per_req_ratio', 'error_ratio', 'dep_fail_rate', 'error_log_rate', 'mem_share', 'mem_slope_share_per_min', 'scratch_mb', 'scratch_slope_mb_per_min', 'up_frac'].
  - forest thresholds per service: web=0.837, orders=0.769, inventory=0.706, payments=0.708
  - learned limits (web): cpu_per_req_ratio: [0.523, 2.02], dep_fail_rate: [-0.05, 0.525], error_log_rate: [-0.025, 0.469], error_ratio: [-0.00791, 0.0881], lat_ratio: [-0.283, 2.7], mem_share: [0.229, 0.279], mem_slope_share_per_min: [-0.0369, 0.0556], scratch_mb: [-2e-11, 2e-11], scratch_slope_mb_per_min: [-2e-11, 2e-11]
- **Classifier**: gradient boosting (NaN-aware) with temperature scaling (T = 0.70); classes ['bad_deploy', 'disk_fill', 'down', 'error_spike', 'healthy', 'latency_spike', 'memory_leak']; confidence abstain threshold 0.40; 44 features (including observed-masks).
- **Novelty gate**: mean distance to the 5 nearest known windows over 12 features; abstain above 1.000 (the 99% quantile of out-of-fold distances).
- **Root-cause ranker**: gradient boosting over 10 evidence features: ['anomaly_score', 'anomalous', 'earliness', 'caller_blame', 'n_anomalous_callees', 'n_anomalous_callers', 'unavailable', 'recent_deploy', 'err_ratio', 'lat_ratio'].
- **Baselines** (healthy medians and spreads per service) for ['web', 'orders', 'inventory', 'payments'].

## Calibration

- out-of-fold ECE 0.0016; ECE on windows predicted as a fault class 0.0099; the dashboard shows the probability as a percentage: True (rule: overall ECE <= 0.05 and fault-prediction ECE <= 0.10 with at least 50 such windows).

## Intended use and limits

- Intended for the four-service demo application in this repository, with the fault types injected by `evaluator/`.
- Trained on one application, on a single machine, with scripted faults and a single workload generator. Do not read these numbers as production accuracy.
- The detector's forest adds nothing measurable over the learned limits (see `docs/results/detector_margin.md`).
- A fault the model has not seen should be answered with an abstention, but the gate can miss faults that resemble a known one (hold-one-fault-type-out numbers are in `docs/results/models_cv.md`).
- The `orders` and `web` baselines drift with container age (`docs/results/runs_sanity.md`); live baselines should be refitted from recent healthy history in a long-running deployment.
